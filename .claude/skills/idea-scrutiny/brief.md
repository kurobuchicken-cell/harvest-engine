# 精査の作業係への頼み(型。<> を埋めて渡す)

日本語で作業・回答する。

## 目的
ビジネス案(担当: <id か束の名前>)を、オーナー(日本に住む個人・法人なし)の口座に入金されるまでの道筋で精査する。精度が一番大事。分からないことは「確かめていない」と書き、推測で埋めない。

## 先に全部読む
1. 観点と手順: C:\dev\harvest-engine\.claude\skills\idea-scrutiny\SKILL.md
2. 調べ方: skill「research-rule」(Skill ツールで読む)
3. 案の記録: C:\dev\harvest-engine\hq\ideas.json の items のうち担当の id(hypothesis・q1〜q3・legal・pivot・reason・test・sources・where・keywords)。記録の主張は仮説として扱う。sources の URL はまず使う
4. 確かめ済みの事実: C:\dev\harvest-engine\hq\scrutiny\known-facts.md(同じことを調べ直さない。担当の売り場・国に当てはまるかは確かめる)
5. <GM が渡す材料: 前の精査の表・開けなかった URL・メモなど>

## やること
1. SKILL.md の手順の <1段目だけ / 2段目> を当てる(0. の★は「オーナーの判断待ち」とだけ書く)
2. 観点ごとに: 答え・印(確かめた/確かめていない/見立て/検証で決まる)・出典の URL・原文の短い引用
3. 「無い」と書くときは SKILL.md の手順6の手段から2つ以上で探し、使った手段を書く
4. 判定の決め手になる事実(◆の答え)は、ページを開いて原文で確かめる。検索の抜粋だけで「確かめた」と書かない
5. ウェブの検索とページの取得だけを使う。ブラウザ(Claude in Chrome)と Perplexity は使わない。開けないページは、同じ答えがありそうな別の道を2つ以上試し、それでもだめなら URL を一覧で返す
6. 外への連絡・登録・申し込み・アカウント作成はしない

## 書くもの
<scratchpad のパス>\<id>.md に(hq/ideas.json は書き換えない):
- 型・束
- 観点ごとの表(番号・答え・印・出典・原文の文)
- 判定(捨てる/検証へ)と理由。検証へなら、残った問いごとに確かめる手段と決める人
- 案の記録と違っていたこと(数字・先行者・値段の誤り)
- 検索の回数・開いたページの数・開けなかった URL

## 返すもの(短く)
- 判定と理由(2〜3行)
- 決め手の事実を最大3つ(URL と原文の文)
- 案の記録と違っていたこと
- 検索の回数・開いたページの数・開けなかった URL
