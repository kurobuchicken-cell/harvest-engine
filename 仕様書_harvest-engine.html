1. 補助金パイロット(テーマP)

出口工場(一次情報の自動収集→AI構造化→ページ自動生成→アフィリエイト・広告)の国内向けパイロット1本目。現段階のゴールは「実データからローカルで静的ページを生成できること」。公開・アフィリエイトは対象外。

1.1 実行方法

コマンド動作
npm run pilot:subsidy収集 → AI分類(未分類のみ) → ページ生成
npm run pilot:subsidy -- --no-aiAI分類を省略(未分類のJ-Net21案件はページに出ない)
npm run pilot:subsidy -- --generate-only収集もせず保存済みデータからページだけ生成

どちらかの情報源の取得に失敗しても、もう一方の収集とページ生成は続行する。AI分類には ANTHROPIC_API_KEY(.env)が必要。

2. ガチャパイロット(テーマQ)

出口工場の海外向けパイロット1本目。日本のガチャ(カプセルトイ)新作の発売予定をメーカー公式から収集し、日本語・英語・フランス語のページを自動生成する。現段階のゴールはローカルでの生成まで。公開・アフィリエイトは対象外。

2.1 実行方法

コマンド動作
npm run pilot:gacha収集 → AI翻訳・作品名付与(未処理のみ) → ページ生成
npm run pilot:gacha -- --no-aiAI処理を省略(未翻訳の商品は日本語名のまま出る)
npm run pilot:gacha -- --generate-only保存済みデータからページだけ生成

2.2 構成

ファイル(src/pilots/gacha/)役割
genre.tsジャンル定義(型=catalog)
collectBandai.tsガシャポン公式の発売スケジュール1か月分を解析(4章のcatalog型のメーカー1社分)
collectTakaraTomyArts.tsタカラトミーアーツのガチャ発売カレンダーを解析、価格は詳細ページから取得
enrich.tsSonnet 5.5で翻訳・作品名・商品種別を付与、費用をledgerに記帳
languages.ts言語設定(画面文言・メーカー名・種別名・発売時期の書式)。言語の追加はここに1要素足すだけ
generate.ts言語別の静的HTML生成
months.ts / types.ts発売月の表記変換・HTML実体参照の復元 / 型(対象月の計算は4章のcatalog型)

2.3 収集元

収集元取得方法規約・注意
ガシャポンオフィシャルサイト(バンダイ)

タカラトミーアーツ ガチャ発売カレンダー

対象月はJST基準の前月・当月・翌月。通信は既存の politeFetch を経由する。商品IDは メーカー:商品コード で、商品名が変わらない限りAI処理結果を引き継ぐ。

2.4 AI処理

  • モデルは claude-sonnet-5-5(effort low)。構造化出力で、各言語の商品名・商品名中の固有名詞・作品名(英語の正式表記、無ければnull)・商品種別(figure / mascot_keychain / plush / miniature / accessory / stationery_goods / other)を返させる。25件ずつ処理する。
  • 作品名は、商品名から導けるものに限る(親会社・上位ブランドを推測しない)。表記揺れを防ぐため、既出の作品名一覧をバッチごとにプロンプトへ渡す。
  • Haiku 4.5では実在しない作品名を当てる誤りがあったため、Sonnet 5.5を採用した(DECISIONS.md 2026-10-05)。
  • 処理済みの商品は再処理しない。言語を追加した場合は、翻訳が欠けた商品だけを再処理する。refusal・max_tokensで止まったバッチは未処理のまま残し、次回の実行で再処理する。
  • 費用は1回の実行につき1行としてledgerに記帳する(service pilot-gacha-sonnet)。402件の全件処理で約$0.53。

2.5 生成ページ

出力先は site/gacha/(git管理外、毎回作り直し)。各言語で同じ相対パスのページを作り、hreflangで相互にリンクする。

パス内容

{lang}/index.html当月以降の発売予定、作品別・メーカー別・月別の索引
{lang}/month/YYYY-MM.html月別
{lang}/maker/{maker}.htmlメーカー別
{lang}/franchise/{slug}.html作品別(ロングテールの主力)。slugは英語の作品名から生成し、重複は警告する
  • 商品ごとに表示するのは、商品名(日本語以外のページでは日本語の原題も併記)、発売時期(言語ごとの書式)、価格、メーカー、種別、再販、作品名、公式ページへのリンク、出典。画像と商品説明文は表示しない。
  • フッターには、非公式サイトであり各メーカーと関係がないこと、機械翻訳であること、各出典を表示する。
  • 2026-10-05時点の実績: 619ページ(各言語206)、402商品、200作品。

3. 値上げ情報パイロット(テーマR)

出口工場の国内パイロット2本目。食品・日用品メーカーが発表した価格改定(値上げ)を集め、実施日順・月別・メーカー別・品目別のページを自動生成する。現段階のゴールはローカルでの生成まで。

3.1 実行方法

コマンド動作
npm run pilot:price収集 → AI抽出(未処理のうち最大40件) → ページ生成
npm run pilot:price -- --no-aiAI抽出を省略
npm run pilot:price -- --generate-only保存済みデータからページだけ生成

取得が打ち切られて裏に残っても、定期実行が重ならないよう処理の最後に必ずプロセスを終了させる。

3.2 構成

ファイル(src/pilots/price/)役割

3.3 収集

  • 監視対象は21社(明治・キユーピー・雪印メグミルク・カゴメ・ネスレ日本・東洋水産・ミツカン・アサヒ飲料・日本ハム・日清オイリオ・丸美屋・日清製粉ウェルナ・不二家・ポッカサッポロ・伊藤ハム・ヤクルト・森永製菓・日清食品HD・伊藤園・UCC・ユニ・チャーム)。2026-10-05に、robots.txtで制限がないこと・既知AIボットの名指しDisallowがないこと・一覧がSSRであることを確認した。2026-10-06から日清製粉ウェルナ・不二家・森永製菓・日清食品HD・ユニ・チャームの5社を停止(サイトの利用規約に営利・商業目的の利用を制限する文言があるため、原文精読まで)。sources.tsのsuspendedに理由を書いた社は、収集・AI抽出・掲載の対象外になる(ACTIVE_SOURCES)。稼働は16社。
  • リンク文言のキーワードは、価格改定・価格改訂・値上げ・出荷価格・価格の改定・価格変更・価格の見直し・内容量変更・規格変更。
  • 告知IDはURLのSHA-1。既知の告知は再登録しない。一覧の1ページ目に載っている告知だけを対象とする。
  • 一覧の取得は45秒、本文の取得は60秒で打ち切る(src/factory/fetch.ts)。politeFetch本体にも1回60秒のタイムアウトがあるが、リトライ込みで最長約4分になるため、さらに短い上限を設けている。
  • 対象外とした会社: 403でアクセス拒否(カルビー・味の素・サントリー)、GPTBotを名指しでDisallow(マルハニチロ)、一覧がJS描画(ロッテ・キッコーマン・エスビー食品)、要再調査(ハウス食品G・キリン・ブルボン・ニッスイ・AGF・花王・山崎製パン)。

3.4 AI抽出

  • モデルは claude-haiku-4-5。告知1件につき1リクエスト。構造化出力で、価格改定かどうか、方向(increase / decrease / mixed / size_only / other)、見出し(自分の言葉で30字以内)、要約(自分の言葉で1〜2文)、発表日・実施日(本文の表記のまま)、改定率の表記と最小・最大%、内容量変更の有無、対象ブランド(最大15件)、品目分類(15種)を返させる。本文に無いことはnullにさせる。
  • 本文の渡し方: PDFはdocumentブロックで渡す。HTMLはテキストに変換して渡し(<main>が空に近いときはページ全体を使う)、本文が短いかPDFへの言及があれば、添付PDFも一緒に渡す。本文が極端に短いときは、JSのlocation.hrefやmeta refreshの転送先を優先して読む。
  • 日付は補助金パイロットのparseJapaneseDateでコード側で換算する。年の無い実施日は発表日を基準にする。発表日が本文に無い場合は、一覧の見出しの日付で補う。
  • 1回の実行で処理するのは最大40件(初回の過去分を平準化するため)。失敗した告知は3回まで再試行する。
  • 2026-10-05の実績: 101件を抽出(エラー0)、費用は約$0.68。

3.5 生成ページ

パス内容
index.htmlこれから実施される値上げ(実施日順)、最近発表された値上げ20件、実施月・メーカー・品目の索引
month/YYYY-MM.htmlその月に実施される値上げ
company/{id}.htmlメーカー別
category/{slug}.html品目別
  • 掲載するのは、価格改定と判定され、方向が increase / mixed / size_only / other のもの。値下げは載せない。size_onlyには「内容量変更(実質値上げ)」、otherには「改定内容は一次情報を参照」と表示し、値上げとは断定しない。
  • 本文は転載しない。表示するのは、AIが書いた見出し・要約、実施日・改定率・発表日・対象ブランド・品目、一次情報へのリンク、「出典：{会社名} ニュースリリース」。フッターには、非公式であることとAI要約であることを明記する。

4. 共通の土台・定期実行・自動点検(出口工場)

3本のパイロットで重複していた処理(保存・AI呼び出しと費用記帳・取得・ページ書き出し)を src/factory/ にまとめ、新ジャンルを「ジャンル定義+型ごとの小さなコード」で足せるようにした。あわせて、VMでの毎日の定期実行と、異常の自動点検・Slack通知を加えた(2026-10-05、DECISIONS.md参照)。

4.1 実行方法

4.4 定期実行

  • 毎日04:00 JST(19:00 UTC)。評議会(月曜09:00 JST)・監査(月曜10:00 JST)とは重ならない。
  • VMの空きメモリが約380MBのため、ジャンルごとに別プロセスで順に実行し、終わるたびにメモリを返す。1ジャンル60分を超えたら打ち切る。前回が終わっていなければその回は飛ばす。

4.5 自動点検(毎回、ページ生成の後)

項目判定

一次情報リンク・出典の欠落掲載カード(li.item)に外部リンクと出典表記(.credit)があるか

5. 一次情報源調査(research:sources)

評議会が採択したジャンルについて、GMが手作業で行っていた「一次情報源の特定・robots.txt/規約の確認」の下調べを自動化する。ジャンルを数十〜数百に増やすときのボトルネックを外すため(2026-10-06、DECISIONS.md参照)。出力は一次判定で、第1層登録の可否はGMが原文を確認して決める。当面は手動起動。週次評議会への自動連結は、手動実行3回または2026-11-02の早い方でオーナーに諮る(HANDOFF.md次アクション5)。

5.1 実行方法

コマンド動作
npm run research:sources -- <裁定JSONのパス>評議会の裁定(council-output/verdicts/*.json)のジャンル名と審議内容を文脈にして調査する
npm run research:sources -- "ジャンル名"評議会を経ないジャンル名の自由入力で調査する
npm run research:sources -- --recheck <調査結果JSONのパス>候補の列挙(検索)はやり直さず、保存済みの候補のrobots.txt・取得・規約だけをチェックし直す(判定ロジックの修正後や、時間をおいた再確認用)

出力は council-output/source-research/{日付}_{ジャンル名}.md(GMが読む表と詳細)と同名の .json。費用はledgerにservice source-research で記帳する。

5.2 処理の流れ

  1. 候補の列挙(AI): Claude Sonnet 5.5(effort medium)がweb_search(1回あたり最大30回)で、一次情報源(メーカー・官公庁・業界団体の公式サイト)の「新しい情報が追加される一覧ページ」を最大12件挙げる。項目は一覧URL・形式(html/rss/api/pdf)・RSS/APIのURL・更新頻度・出口工場の型(catalog/announcement/api/none)・規約URL・根拠。ニュースサイト等の二次情報は除外。
  2. 機械チェック(コード、AI不使用):
    • robots.txt: 自ボット(HarvestEngineBot)が一覧URLを取得できるか。既知のAIボット(GPTBot・ClaudeBot・CCBot・anthropic-ai等12種)を名指しでDisallowしているか(CLAUDE.md「巡回対象選定の追加ルール」)。403・418・5xxはWAFによるブロックの可能性があり「判定不能」とする
    • 一覧ページの取得: HTTP状態、PDFか、本文の長さとリンク数。本文が300字未満、またはリンクが少なくSPAの枠(id="root"等)だけのページは「JS描画疑い」(現行の巡回方式では拾えない)
    • RSS/API: 指定されたURL、またはページ内の<link rel=alternate>で見つけたフィードが応答するか
    • 規約ページ: 一覧ページ内の「利用規約」「サイトポリシー」「ご利用にあたって」「著作権」等のリンクを拾う。一覧ページと同じホストの規約リンクを、AIが挙げた規約URLより優先する(府省のサブサイトが親組織と別の規約を持つことがあるため)
  3. 規約の一次要約(AI): 規約ページの本文(先頭3万字まで、超えた場合は出力に明記)をClaude Sonnet 5.5(effort low)が読み、自動取得・転載/再利用・商用利用を「禁止/条件付き/記載なし/不明」で分類し、根拠の条文を抜粋する。「禁止」は条文の抜粋がある場合のみ有効(無ければ「不明」に倒す)。Haiku 4.5では例外条項の範囲を読み分けられず判定が揺れたためSonnetを使う。

5.3 判定

判定条件
不可robots.txtで自ボットの取得が禁止 / AIボットを名指しで拒否 / 規約で自動取得が禁止(条文あり)
要確認robots.txtが判定不能 / 一覧ページを取得できない / JS描画疑い / RSS・APIが応答しない / 規約ページ未特定・取得不可・読み取り不能 / 規約で転載が禁止 / 規約で商用利用が禁止または要許可(一部コンテンツに限る例外条項は「条件付き」扱い) / 規約が長く一部のみ確認
登録候補上記のいずれにも当たらない
