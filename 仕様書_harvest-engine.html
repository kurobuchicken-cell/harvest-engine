1. 補助金パイロット(テーマP)

出口工場(一次情報の自動収集→AI構造化→ページ自動生成→アフィリエイト・広告)の国内向けパイロット1本目。現段階のゴールは「実データからローカルで静的ページを生成できること」。公開・アフィリエイトは対象外。

1.1 実行方法

コマンド動作
npm run pilot:subsidy収集 → AI分類(未分類のみ) → ページ生成
npm run pilot:subsidy -- --no-aiAI分類を省略(未分類のJ-Net21案件はページに出ない)
npm run pilot:subsidy -- --generate-only収集もせず保存済みデータからページだけ生成

どちらかの情報源の取得に失敗しても、もう一方の収集とページ生成は続行する。AI分類には ANTHROPIC_API_KEY(.env)が必要。

収集元取得方法規約・注意
jGrants公開API(デジタル庁)
api.jgrants-portal.go.jp/exp/v1/public		 一覧APIはキーワード2文字以上が必須で全件一括取得できないため、10語(補助・助成・支援・事業・交付・奨励・給付・促進・対策・推進)を受付中(acceptance=1)で検索し、IDで重複を除く。各案件は詳細APIを1秒間隔で取得。一覧の締切値が前回と同じ案件は詳細APIを呼ばない。 robots.txtは404(制限なし)。Web-API利用規約(fs2.jgrants-portal.go.jp/API利用規約.pdf、2026-10-05確認): 商用利用の禁止なし、出典「出典：Jグランツ」必須、編集・加工した場合は加工した旨と「政府・自治体の保証ではない」旨の記載が必須、短時間の大量アクセス・事実に反する内容は禁止、ベータ版のため予告なく停止しうる。詳細APIは添付PDFのbase64を含み重い。一覧と詳細で締切が食い違う案件があるため、表示には詳細側を使い、再取得の判定には一覧側を使う。

1.4 分類

軸語彙jGrantsJ-Net21
地域47都道府県+全国APIの対象地域。地方ブロック名は構成都道府県に展開し、47都道府県すべてを含む場合は全国とするRSSの dc:coverage
業種日本標準産業分類の大分類19種(空=業種を問わない)APIの業種。16種以上を列挙した案件は「業種を問わない」とみなす。「分類不能の産業」は無視するAI
目的jGrantsの利用目的15種APIの利用目的AI(1〜3個)
締切日時APIAIは本文の表記のまま抜き出し、コードで西暦に換算する(年の書かれていない日付は掲載日以降で最も近い日付とする)
  • AIモデルは claude-haiku-4-5。構造化出力(JSONスキーマ、業種・目的はenumで制約)を使い、1リクエストで20件ずつ処理する。
  • 分類済みの案件は再分類しない。かかった費用は1回の実行につき1行として data/ledger.json に記帳する(費目api、service pilot-subsidy-haiku)。実績は64件で約$0.048(約8円)。
  • jGrantsは元の値(sourceFields)を保存しておき、毎回の実行で正規化し直す。分類表を直しても再取得は不要。
  • 語彙に無い値は捨てずに、実行終了時に一覧を表示する(分類表への追加漏れの検知用)。

1.5 データ保存

data/pilots/subsidy/items.json(git管理外)。パイロットの間はDBスキーマを変更しない。主な項目は id(source:元ID)、title、url、kind(grant/loan)、regions、industries、purposes、acceptanceEnd、classifiedBy(source/ai/pending)、firstSeenAt/lastSeenAt、sourceFields(jGrants)、rawText(J-Net21、ページには出さない)。

1.6 生成ページ

出力先は site/subsidy/(git管理外)。前回分が残らないよう、毎回いったん削除してから作り直す。リンクはすべて相対パスで、file:// で開いても辿れる。

パス内容生成条件
index.html地域・業種・目的の索引(件数付き)、新着30件常に生成
region/{pref}/index.htmlその地域限定の案件(全国対象は全国ページへ誘導)、目的別・業種×目的別の絞り込みリンク1件以上(全国は常に生成)
region/{pref}/p-{purpose}.html地域×目的1件以上
region/{pref}/{industry}/{purpose}.html地域×業種×目的。業種を問わない同条件の案件と、全国対象の同条件の案件を別の欄で併記業種を特定した案件が1件以上
industry/{industry}/index.html、industry/any/index.html業種別/業種を問わない1件以上
purpose/{purpose}/index.html目的別1件以上
  • 掲載対象は、締切が未来の案件と、締切不明のJ-Net21案件のうち掲載から60日以内のもの。未分類の案件は掲載しない。
  • 各案件には出典を表示する(「出典：Jグランツ」/「出典：中小機構 J-Net21」)。フッターには両方の出典と、jGrants利用規約第5条1項二の記載例に沿った加工表示(「このコンテンツは、政府公式の補助金申請システム jGrants の Web-API 機能を利用して取得した情報をもとに作成者名にて作成されたものです。コンテンツの内容は日本国政府及び自治体によって保証されたものではありません。」)を表示する。作成者名は公開時にオーナーが決めるまで「本サイト運営者」と仮置き(generate.tsのOPERATOR_NAME)。
  • リンク先は各出典の公式ページ(rel="nofollow noopener")。
  • 2026-10-05時点の実績: 820ページ(組み合わせ741)、掲載397件。

2. ガチャパイロット(テーマQ)

出口工場の海外向けパイロット1本目。日本のガチャ(カプセルトイ)新作の発売予定をメーカー公式から収集し、日本語・英語・フランス語のページを自動生成する。現段階のゴールはローカルでの生成まで。公開・アフィリエイトは対象外。

2.1 実行方法

コマンド動作
npm run pilot:gacha収集 → AI翻訳・作品名付与(未処理のみ) → ページ生成
npm run pilot:gacha -- --no-aiAI処理を省略(未翻訳の商品は日本語名のまま出る)
npm run pilot:gacha -- --generate-only保存済みデータからページだけ生成

2.2 構成

ファイル(src/pilots/gacha/)役割
run.tsエントリポイント
collectBandai.tsガシャポン公式の発売スケジュールを解析
collectTakaraTomyArts.tsタカラトミーアーツのガチャ発売カレンダーを解析、価格は詳細ページから取得
enrich.tsSonnet 5.5で翻訳・作品名・商品種別を付与、費用をledgerに記帳
languages.ts言語設定(画面文言・メーカー名・種別名・発売時期の書式)。言語の追加はここに1要素足すだけ

months.ts / store.ts / types.ts対象月の計算・HTML実体参照の復元 / JSONストア / 型

2.3 収集元

収集元取得方法規約・注意
ガシャポンオフィシャルサイト(バンダイ)
gashapon.jp/schedule/?ym=YYYYMM		 週見出し(「10月第1週より順次」等)ごとに商品カードを読む。商品名・価格・JANコード・再販フラグを取得。スケジュール欄以外のランキング等は読まない。 robots.txtは404(制限なし)、既知AIボット名指しなし。画像・商品説明文は掲載しない。
タカラトミーアーツ ガチャ発売カレンダー

対象月はJST基準の前月・当月・翌月。通信は既存の politeFetch を経由する。商品IDは メーカー:商品コード で、商品名が変わらない限りAI処理結果を引き継ぐ。

2.4 AI処理

  • モデルは claude-sonnet-5-5(effort low)。構造化出力で、各言語の商品名・商品名中の固有名詞・作品名(英語の正式表記、無ければnull)・商品種別(figure / mascot_keychain / plush / miniature / accessory / stationery_goods / other)を返させる。25件ずつ処理する。
  • 作品名は、商品名から導けるものに限る(親会社・上位ブランドを推測しない)。表記揺れを防ぐため、既出の作品名一覧をバッチごとにプロンプトへ渡す。
  • Haiku 4.5では実在しない作品名を当てる誤りがあったため、Sonnet 5.5を採用した(DECISIONS.md 2026-10-05)。
  • 処理済みの商品は再処理しない。言語を追加した場合は、翻訳が欠けた商品だけを再処理する。refusal・max_tokensで止まったバッチは未処理のまま残し、次回の実行で再処理する。
  • 費用は1回の実行につき1行としてledgerに記帳する(service pilot-gacha-sonnet)。402件の全件処理で約$0.53。

2.5 生成ページ

出力先は site/gacha/(git管理外、毎回作り直し)。各言語で同じ相対パスのページを作り、hreflangで相互にリンクする。

パス内容
index.html言語選択
{lang}/index.html当月以降の発売予定、作品別・メーカー別・月別の索引
{lang}/month/YYYY-MM.html月別
{lang}/maker/{maker}.htmlメーカー別
{lang}/franchise/{slug}.html作品別(ロングテールの主力)。slugは英語の作品名から生成し、重複は警告する
  • 商品ごとに表示するのは、商品名(日本語以外のページでは日本語の原題も併記)、発売時期(言語ごとの書式)、価格、メーカー、種別、再販、作品名、公式ページへのリンク、出典。画像と商品説明文は表示しない。
  • フッターには、非公式サイトであり各メーカーと関係がないこと、機械翻訳であること、各出典を表示する。
  • 2026-10-05時点の実績: 619ページ(各言語206)、402商品、200作品。

3. 値上げ情報パイロット(テーマR)

出口工場の国内パイロット2本目。食品・日用品メーカーが発表した価格改定(値上げ)を集め、実施日順・月別・メーカー別・品目別のページを自動生成する。現段階のゴールはローカルでの生成まで。

3.1 実行方法

コマンド動作
npm run pilot:price収集 → AI抽出(未処理のうち最大40件) → ページ生成
npm run pilot:price -- --no-aiAI抽出を省略
npm run pilot:price -- --generate-only保存済みデータからページだけ生成

取得が打ち切られて裏に残っても、定期実行が重ならないよう処理の最後に必ずプロセスを終了させる。

3.2 構成

ファイル(src/pilots/price/)役割
sources.ts監視対象の会社とニュースリリース一覧URL(会社の追加はここに1行足すだけ)。prisma/seed.tsもこれを読み込む
collect.ts一覧ページから、リンク文言がキーワードに当たる告知を抽出する(社ごとの専用パーサーなし)
analyze.ts告知の本文(HTML/PDF)をHaiku 4.5で構造化し、費用をledgerに記帳する
fetchUtil.tsタイムアウト付き取得、文字コード判定(Shift_JIS/EUC-JP対応)、HTML→テキスト、PDF判定
generate.ts / run.ts / store.ts / types.tsページ生成 / エントリポイント / JSONストア / 型

3.3 収集

  • 監視対象は21社(明治・キユーピー・雪印メグミルク・カゴメ・ネスレ日本・東洋水産・ミツカン・アサヒ飲料・日本ハム・日清オイリオ・丸美屋・日清製粉ウェルナ・不二家・ポッカサッポロ・伊藤ハム・ヤクルト・森永製菓・日清食品HD・伊藤園・UCC・ユニ・チャーム)。2026-10-05に、robots.txtで制限がないこと・既知AIボットの名指しDisallowがないこと・一覧がSSRであることを確認した。
  • リンク文言のキーワードは、価格改定・価格改訂・値上げ・出荷価格・価格の改定・価格変更・価格の見直し・内容量変更・規格変更。
  • 告知IDはURLのSHA-1。既知の告知は再登録しない。一覧の1ページ目に載っている告知だけを対象とする。
  • 一覧の取得は45秒、本文の取得は60秒で打ち切る。politeFetch本体にも1回60秒のタイムアウトがあるが、リトライ込みで最長約4分になるため、パイロット側でさらに短い上限を設けている。
  • 対象外とした会社: 403でアクセス拒否(カルビー・味の素・サントリー)、GPTBotを名指しでDisallow(マルハニチロ)、一覧がJS描画(ロッテ・キッコーマン・エスビー食品)、要再調査(ハウス食品G・キリン・ブルボン・ニッスイ・AGF・花王・山崎製パン)。

3.4 AI抽出

  • モデルは claude-haiku-4-5。告知1件につき1リクエスト。構造化出力で、価格改定かどうか、方向(increase / decrease / mixed / size_only / other)、見出し(自分の言葉で30字以内)、要約(自分の言葉で1〜2文)、発表日・実施日(本文の表記のまま)、改定率の表記と最小・最大%、内容量変更の有無、対象ブランド(最大15件)、品目分類(15種)を返させる。本文に無いことはnullにさせる。
  • 本文の渡し方: PDFはdocumentブロックで渡す。HTMLはテキストに変換して渡し(<main>が空に近いときはページ全体を使う)、本文が短いかPDFへの言及があれば、添付PDFも一緒に渡す。本文が極端に短いときは、JSのlocation.hrefやmeta refreshの転送先を優先して読む。
  • 日付は補助金パイロットのparseJapaneseDateでコード側で換算する。年の無い実施日は発表日を基準にする。発表日が本文に無い場合は、一覧の見出しの日付で補う。
  • 1回の実行で処理するのは最大40件(初回の過去分を平準化するため)。失敗した告知は3回まで再試行する。
  • 2026-10-05の実績: 101件を抽出(エラー0)、費用は約$0.68。

パス内容

  • 掲載するのは、価格改定と判定され、方向が increase / mixed / size_only / other のもの。値下げは載せない。size_onlyには「内容量変更(実質値上げ)」、otherには「改定内容は一次情報を参照」と表示し、値上げとは断定しない。
